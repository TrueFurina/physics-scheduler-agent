### 2.4 历史决策复盘：D-2（v5）为什么不适用于今天

安全清单 D-2 记录（v5）：「把 schedule.xlsx 移出仓库」⛔ 不建议——与「线上显示真实

## 3. 选项对比

| 选项 | 做法 | 功能影响 | 回归强度 | 上传面 | 成本 |
|---|---|---|---|---|---|
| a. 维持现状 | 双闸门（冻结 + preflight 存在性拦截） | 无 | 满（41 真实表用例） | 🔴 解冻即裸奔 | 0 |
| b. 移出仓库 | 文件移到仓库外，`SCHEDULE_PATH`/测试路径指向外部 | 无 | ⚠️ 无外部文件的机器上 41 用例全 skip（CI 本就 skip；本地强度取决于外部文件在不在） | 🟢 根治 | 中（路径约定 + 文档 + 自包含性破） |
| c. 脱敏联系表 B 列 | 17 格手机号 → 占位符（如 `1xxxxxxxxxx`），其余内容不动 | **零**（该列无读取路径；姓名/备注/角色功能全保留） | 满（主表未动，433 条原样） | 🟢 无个人 PII | 低（一次手术 + 回归） |
| d. 删「系办电话」sheet | 整表删除 | 零（无解析路径） | 无影响 | 🟢 更干净 | 低 |
| e. 删整个「教师联系表」 | — | 🔴 **破坏** `get_teacher_roles`（负责人/管理员角色丢失） | 降 | 🟢 | — |

**c+d 叠加**是推荐组合：个人 PII（c 必须）+ 机构号表（d 可选加分，删 sheet 改动
更大、敏感度低，不强制）。

### 选项 c 的两个诚实代价（写进 docstring，不许装作没发生）

1. 「真实表」变成「真实表-净化版」：姓名/班级/项目/排课全真，仅联系表电话列假。
   主表解析口径零变化 ⇒ `test_real_table_baseline` 等基线不受影响。
2. 隐私测试的**真实数据层断言变弱**（源文件已无毒，该层从"判据"变"回归"）——
   可接受，因为 PII 守卫职责本就在**合成带毒层**（`TOXIC_PHONES` 注入 + 零泄露断言），
   那才是 R-25 意义上的判据。手术后更新该测试 docstring 注明净化日期，防止误读。

---

## 4. 建议：c（+可选 d）

理由：

1. **精确手术、零功能代价**：B 列无任何读取路径是实测的（`_parse_teacher_roles`
   只取 row[0]/row[3]）；主表 0 PII 也是实测的。改 17 个格子不影响 399 个测试中的
   任何一个断言（它们不读电话列）。
2. **保留 R-55 真实数据回归强度**：b 选项让本地回归强度取决于"外部文件在不在"，
   是把确定性换成运气；c 不动主表，强度不掉。
3. **与产品目标一致**：线上真实姓名（R-09）不受任何影响；D-2 的合理内核
   （主表在沙箱内）被完整保留。
4. **终态判据升级**（比"文件在不在"更正确的闸门）：preflight 从"schedule.xlsx
   存在 ⇒ ❌"改为"**内容检测**：文件内无手机号/邮箱形态 ⇒ 放行；有则 ❌"。
   手术后存在性拦截就误伤了（每次 preflight 都红），而内容检测才是与威胁模型
   对齐的判据。

若追求更彻底（沙箱内零敏感表）：叠加 d，或再考虑 b——但 b 的回归强度代价实在，
不建议在本轮做。

## 5. 若批准 c（+d）的执行清单

```
0. 备份：cp schedule.xlsx → 备份名必须被 .gitignore 覆盖（§2.1 实测 .bak 不忽略！
   ⇒ 先给 .gitignore 加 schedule.xlsx* 一行，或备份到仓库外固定路径）
1. 手术脚本（openpyxl 非 read_only）：教师联系表 B3:B19 → "1xxxxxxxxxx"；
   若选 d：wb.remove(wb['学生所在系系办电话'])；保存
2. 解析缓存自动失效（签名=path+mtime_ns+size）⇒ 无需 bump CACHE_VERSION
   （主表内容未变，但文件字节变了，缓存自然重解析——勿手动 bump，那是噪声）
3. 全量回归：后端 399 应**一条不掉**（主表未动）；前端不涉及
4. 更新 test_privacy_export.py 真实数据层 docstring（注明净化日期 + 判据已移交合成层）
5. preflight_release.py：存在性拦截 → 内容检测（扫 schedule.xlsx 无 PII 形态才放行）
6. 安全文档追加修订 v24（手术记录 + D-2 结论修订：旧结论对主表仍成立，对联系表不成立）
7. 提交（schedule.xlsx 本体仍不被跟踪，提交的是代码/文档/ignore 变更）
```

反假绿判据（R-25）：手术后的隐私测试若把占位符改回真实形态（缺陷版），合成带毒层
必须仍然红——它本来就是注入式判据，不受源文件影响；这正说明判据放对了一层。
