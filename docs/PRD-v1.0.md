## 1. 产品概述

### 1.1 一句话定位

面向高校物理实验教学场景的 **四大模块智能体系统**：排课、选课、调课、辅导，用 AI 对话降低操作门槛、用规则引擎保证排课结果可靠。

> 〔V1.0 原文存档。**现行口径为三大模块：排课、调课、实验规范查询**——选课已移除、辅导改为实验规范查询，见顶部边界更新。〕

### 1.2 项目背景

- 物理实验教学涉及多专业、多教师、多实验室的复杂排课约束
- 教务系统管不了实验排课（论文验证："实验课很少进排课系统，靠人工协调"）
- 教师调课引发多班多教室连锁冲突，人工协调效率低
- 学生选课受先修课/学分约束，看不懂培养方案〔该痛点后经真实访谈验证为伪需求（公共必修强制必选）；选课模块已移除，见顶部边界更新〕

### 1.3 产品目标

解决"排课协调难、调课冲突多、~~选课咨询难~~、实验辅导缺"四大问题，为教师、~~学生~~、管理员提供 AI 辅助的完整闭环。

> 〔存档标注：**选课咨询已移除**（学生事务永久不做）；"实验辅导"已改造为面向**排课人员/教师**的**实验规范查询**。见顶部边界更新。〕

## 4. 核心流程

### 4.1 排课调课流程

```
身份选择（教师卡片）→ 我的课程（可调/不可调）
  → 模板表单（选课程 + 目标周次）→ 冲突筛选
  → 结果（可用时段 + 被排除原因 + AI候选方案）
  → 提交申请 → 管理员审批（同意/驳回）→ 反馈教师
```

### 4.2 选课/辅导流程〔选课已移除；辅导现为「实验规范查询」，见顶部边界更新〕

```
选择模块（实验规范查询；原「选课咨询」已移除）→ 输入问题 → LLM 基于上下文回答 → 展示
```

### 4.3 多轮追问（调课信息不全时）

```
输入"我想调个课" → 系统追问（教师？哪门课？调到哪周？）→ 用户补充 → 继续处理
```

## 5. 功能需求明细

### F1 教师身份选择
- 展示全部教师卡片（从实验安排表提取）
- 点击进入该教师的调课工作台

### F2 我的课程列表
- 展示教师名下全部课程卡片
- 标注【可调/不可调】+ 不可调原因
- 时间友好显示（567 → 13:30-15:45）

### F3 模板表单调课
- 选课程 → 下拉选目标周次 → 自动查询
- 减少自由文本输入（评审建议）

### F4 冲突筛选 + 原因标注
- ~~三重检查：教室占用/学生课表/教师时间~~ **现行三类：教室占用 / 教师时间 / 整组（同班同组）**——"学生课表"腿已移除，见顶部边界更新
- 每个被排除时段附原因（信息透传，评审核心要求）

### F5 自然语言调课（LLM）
- 大白话解析："我是吴琳，下周三有事，把实验课往后挪一周"
- 规则解析失败时降级到 LLM

### F6 管理员审批流
- 教师提交申请（待审批）→ 管理员同意/驳回 → 反馈

### F7 选课咨询（LLM）〔❌ 已移除，见顶部边界更新〕
- ~~选课资格、先修课、学分问题自然语言问答~~（V1.0 原文存档）
- **2026-10-23 已移除**：前后端代码与 `/api/reschedule/course-select` 端点均已删除；系统永久不处理学生事务

### F8 实验辅导（LLM）〔已改造为「实验规范查询」，见顶部边界更新〕
- **现行定位**：面向**排课人员 / 教师**的**实验规范查询**——回答实验项目的**学时、所需场地、操作步骤、数据处理与误差分析规范、报告规范**，服务于排课核对（端点仍为 `/api/reschedule/experiment-tutor`）
- ~~面向学生的实验原理、数据处理、误差分析、报告规范问答~~（V1.0 原文存档）

### F9 AI 候选方案
- LLM 从可用时段生成 2-3 个候选 + 推荐理由
- LLM 不可用时规则降级
