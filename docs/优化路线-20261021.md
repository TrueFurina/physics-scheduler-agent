| # | 优化 | 改动 | 实测效果 |

### 这一批踩到的真坑（值得记住）

**"我把视图做成懒加载了" ≠ "它真的不在首屏"**。第一次只改了 `React.lazy`，构建出来的
`vendor` 仍是 166.6 kB，且 `index.html` 依然 `preload` 它 —— 因为 `manualChunks` 把
**axios（首屏静态必需，`api/client.ts` 用它）和整条 markdown 解析链塞进了同一个 `vendor`**，
于是首屏为了 axios 把 markdown 也一起拖了下来，懒加载白做。

判定方法（别靠肉眼）：

```bash
grep -oE 'from"\./[A-Za-z0-9_-]+\.js"' webui/assets/index-*.js | sort -u   # 静态依赖
grep -oE '(src|href)="/assets/[^"]*"' webui/index.html                       # 预加载清单
```

修法：`manualChunks` 里给 axios 单独一块（`http`）。之后 `index.html` 预加载只剩
`index.js + react-vendor + http + css`，`vendor`（117.8 kB，纯 markdown 链）退出关键路径。

> 顺带修掉一个真缺陷：调课沙盘里 `['567','678','91011'].map(ts => (<>…</>))` 的外层
> Fragment **没有 key**（并行排课那边写了 `<Fragment key={ts}>`，这边漏了），React 会报
> key 警告。拆到 `RescheduleView` 时改成 `<Fragment key={ts}>`。

## 一·D、第四批：补上「懒加载引入的新崩溃面」——视图级错误边界（2026-10-21 16:20）

上一批为了首屏体积加了三个 `React.lazy`。**这是一次自己给自己制造风险的操作**：在 React 18 里，
渲染期任何抛错若无人接管，会把**整棵树**卸载 —— 用户看到纯白页面，连顶部导航一起消失。
而 `import()` 的 chunk 请求失败（网络抖动、部署切换瞬间、代理层 5xx、浏览器缓存被清）
正是渲染期抛错，`Suspense` 只接 pending、**不接 error**。

关键点：这不是"理论上可能"，而是"加懒加载就必然新增"的失败模式。原来全同步 import 时，
chunk 失败会表现为首屏 HTML 拿不到 JS（浏览器原生白屏，但那是**加载前**）；
现在页面已经跑起来了、用户点了一下按钮才去拉 chunk，失败了就整页消失 —— 用户体验上更糟，
因为他已经在系统里、可能刚填好调课表单。

### 做法

| 项 | 内容 |
|---|---|
| 组件 | `src/components/ErrorBoundary.tsx`（类组件，`getDerivedStateFromError`） |
| 挂载位置 | `<main>` 内容区整体包一层，**`key={view}`** ⇒ 切视图自动重置，不会"一次崩溃永久废墟" |
| 错误分流 | 识别 5 种浏览器的 chunk 失败措辞（Chrome / Safari / Firefox / webpack 系）⇒ 文案「页面资源已更新，需要重新加载」+ 按钮走 `location.reload()`；其余渲染异常 ⇒「这个模块遇到了问题」+ 重试 + 折叠的「技术详情」 |
| 为什么 chunk 错误不给「重试」 | 同一 URL 的模块记录已被标记失败，重挂载边界必然再失败；只有重拉 `index.html`（新哈希）才有救 |

### 反证（这是本项目要求的标准：先证明"病是真的"）

在**同一份产物**上，只删掉边界的两行 JSX 与 import，重新构建，然后用 Playwright
`route.abort()` 掐断 `ParallelView-*.js`，再点「并行排课」：

| 版本 | `#root` 子节点数 | 页面文本长度 | 顶部导航 | 提示卡 |
|---|---|---|---|---|
| 无边界（对照） | **0** | **0 字** | **消失** | 无 |
| 有边界 | 1 | 197 字 | **仍在** | 有 |

即：**没有边界就是教科书式白屏**（`rootChildren: 0`），且用户无法自救；
有边界时教秘能看见原因、能切到别的功能继续干活。

### 验证

| 项 | 结果 |
|---|---|
| `npm test` | **24 → 30 passed**（新增 `ErrorBoundary.test.tsx` 6 项：五种浏览器措辞全认、5 类普通错误不误判、无错时不影响正常渲染、异常时错误细节只进折叠区、重试能恢复、「chunk 场景不给重试」） |
| `pytest` | **123 passed**（未动后端） |
| `probe_ui_flow.cjs` | **8/8 → 9/9**（新增第 9 项「🛟 懒加载失败降级」：故意 abort 一个按需 chunk，断言提示卡出现**且**顶部导航仍可用） |
| `probe_demo_path.cjs` | **10/10**（登录三法 + 微信扫码不受影响） |

> 探针里这项刻意**单独开一个浏览器上下文**：它要制造失败请求，若混在主上下文会把
> 「全程失败请求＝0」这条基线永久染红，让人以后不再相信这条检查。
>
> 顺手修掉一个 `tsc` 拦下的问题：只 `throw` 的函数返回值被推断为 `void`，
> TS2786「不能作为 JSX 组件」。这类错误 `vitest`（esbuild 转译、不做类型检查）**不会报**，
> 只有 `npm run build` 里的 `tsc -b` 会 —— 所以**别只用 `npm test` 当"绿"的证据**。

## 三、评估过但不建议做的（留档以免重排）

| 想法 | 结论 |
|---|---|
| 把排课数据放 Redis / 外部存储 | ❌ 沙箱单进程有状态，引入外部依赖换取"跨重启存活"不划算。R-18 已用"自愈 + 前端重试"解决可用性，成本低两个数量级 |
| 给数据接口加鉴权 | ❌ 教秘主路径（教师选择/沙盘/冲突/排课/体检/统计）必须免登录，加了直接废演示。治理手段是限流，不是门禁 |
| 加大 gzip 级别 / 换 brotli | ⚠️ 边际。已是 zlib level 9；brotli 需额外依赖且沙箱不保证支持，收益约再降 10–15KB，不值得引入构建复杂度 |
| 缩短 `parallel/solve` 的 CP-SAT 时限 | ❌ 24/24 是演示的核心结论，降时限换速度会牺牲"全排定"，本末倒置 |
| 前端全量重写为 Next.js/SSR | ❌ 单页内部工具、无 SEO 需求，改造收益为负 |
