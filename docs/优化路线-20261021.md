### 这一批踩到的真坑（值得记住）

**"我把视图做成懒加载了" ≠ "它真的不在首屏"**。第一次只改了 `React.lazy`，构建出来的
`vendor` 仍是 166.6 kB，且 `index.html` 依然 `preload` 它 —— 因为 `manualChunks` 把
**axios（首屏静态必需，`api/client.ts` 用它）和整条 markdown 解析链塞进了同一个 `vendor`**，
于是首屏为了 axios 把 markdown 也一起拖了下来，懒加载白做。

判定方法（别靠肉眼）：

```bash
grep -oE 'from"\./[A-Za-z0-9_-]+\.js"' webui/assets/index-*.js | sort -u   # 静态依赖
grep -oE '(src|href)="/assets/[^"]*"' webui/index.html                       # 预加载清单
```

修法：`manualChunks` 里给 axios 单独一块（`http`）。之后 `index.html` 预加载只剩
`index.js + react-vendor + http + css`，`vendor`（117.8 kB，纯 markdown 链）退出关键路径。

> 顺带修掉一个真缺陷：调课沙盘里 `['567','678','91011'].map(ts => (<>…</>))` 的外层
> Fragment **没有 key**（并行排课那边写了 `<Fragment key={ts}>`，这边漏了），React 会报
> key 警告。拆到 `RescheduleView` 时改成 `<Fragment key={ts}>`。

## 一·D、第四批：补上「懒加载引入的新崩溃面」——视图级错误边界（2026-10-21 16:20）

上一批为了首屏体积加了三个 `React.lazy`。**这是一次自己给自己制造风险的操作**：在 React 18 里，
渲染期任何抛错若无人接管，会把**整棵树**卸载 —— 用户看到纯白页面，连顶部导航一起消失。
而 `import()` 的 chunk 请求失败（网络抖动、部署切换瞬间、代理层 5xx、浏览器缓存被清）
正是渲染期抛错，`Suspense` 只接 pending、**不接 error**。

关键点：这不是"理论上可能"，而是"加懒加载就必然新增"的失败模式。原来全同步 import 时，
chunk 失败会表现为首屏 HTML 拿不到 JS（浏览器原生白屏，但那是**加载前**）；
现在页面已经跑起来了、用户点了一下按钮才去拉 chunk，失败了就整页消失 —— 用户体验上更糟，
因为他已经在系统里、可能刚填好调课表单。

### 做法

| 项 | 内容 |
|---|---|
| 组件 | `src/components/ErrorBoundary.tsx`（类组件，`getDerivedStateFromError`） |
| 挂载位置 | `<main>` 内容区整体包一层，**`key={view}`** ⇒ 切视图自动重置，不会"一次崩溃永久废墟" |
| 错误分流 | 识别 5 种浏览器的 chunk 失败措辞（Chrome / Safari / Firefox / webpack 系）⇒ 文案「页面资源已更新，需要重新加载」+ 按钮走 `location.reload()`；其余渲染异常 ⇒「这个模块遇到了问题」+ 重试 + 折叠的「技术详情」 |
| 为什么 chunk 错误不给「重试」 | 同一 URL 的模块记录已被标记失败，重挂载边界必然再失败；只有重拉 `index.html`（新哈希）才有救 |

### 反证（这是本项目要求的标准：先证明"病是真的"）

在**同一份产物**上，只删掉边界的两行 JSX 与 import，重新构建，然后用 Playwright
`route.abort()` 掐断 `ParallelView-*.js`，再点「并行排课」：

| 版本 | `#root` 子节点数 | 页面文本长度 | 顶部导航 | 提示卡 |
|---|---|---|---|---|
| 无边界（对照） | **0** | **0 字** | **消失** | 无 |
| 有边界 | 1 | 197 字 | **仍在** | 有 |

即：**没有边界就是教科书式白屏**（`rootChildren: 0`），且用户无法自救；
有边界时教秘能看见原因、能切到别的功能继续干活。

### 验证

| 项 | 结果 |
|---|---|
| `npm test` | **24 → 30 passed**（新增 `ErrorBoundary.test.tsx` 6 项：五种浏览器措辞全认、5 类普通错误不误判、无错时不影响正常渲染、异常时错误细节只进折叠区、重试能恢复、「chunk 场景不给重试」） |
| `pytest` | **123 passed**（未动后端） |
| `probe_ui_flow.cjs` | **8/8 → 9/9**（新增第 9 项「🛟 懒加载失败降级」：故意 abort 一个按需 chunk，断言提示卡出现**且**顶部导航仍可用） |
| `probe_demo_path.cjs` | **10/10**（登录三法 + 微信扫码不受影响） |

> 探针里这项刻意**单独开一个浏览器上下文**：它要制造失败请求，若混在主上下文会把
> 「全程失败请求＝0」这条基线永久染红，让人以后不再相信这条检查。
>
> 顺手修掉一个 `tsc` 拦下的问题：只 `throw` 的函数返回值被推断为 `void`，
> TS2786「不能作为 JSX 组件」。这类错误 `vitest`（esbuild 转译、不做类型检查）**不会报**，
> 只有 `npm run build` 里的 `tsc -b` 会 —— 所以**别只用 `npm test` 当"绿"的证据**。

## 一·E、第五批：把探针从"手工仪式"变成一条命令（2026-10-21 16:28）

之前每次跑 UI 探针都得手敲一长串：

```bash
# 旧做法：必须先进受管 workspace、必须设 NODE_PATH、必须写死 node 与浏览器路径
cd C:/Users/Lenovo/.workbuddy/binaries/node/workspace
NODE_PATH=".../node_modules" "<受管 node 绝对路径>" SITE=http://127.0.0.1:8020/ E:/Program/physics-scheduler-agent/scripts/probe_ui_flow.cjs
```

这不是"麻烦"，而是**探针进不了 CI 的真实原因**：依赖解析和浏览器路径都写死在别人机器上。
本轮把它拆掉。

| 改动 | 说明 |
|---|---|
| 新增 `scripts/_browser.cjs` | 共用装配：`playwright-core` 按候选列表兜底（项目依赖 → 受管 workspace → `PW_CORE_PATH`）；浏览器**自动发现**（`CHROME` → Playwright 缓存里修订号最大的 `chromium-*` → 系统 Chrome/Edge）；统一 `--no-proxy-server` |
| 去掉硬编码 `chromium-1243` | 原先浏览器一升级，两个探针同时报 "file not found"，看起来像代码坏了。现在取最新一份 |
| `playwright-core@1.64.1` 进 `devDependencies` | 版本**对齐**受管 workspace 里那份（它配的正是现有 Chromium），漂移会导致 CDP 不匹配 |
| npm 脚本 | `npm run probe` / `npm run probe:demo` / `npm run verify`（= `tsc -b && vitest run`） |

现在只需要：`cd frontend && SITE=http://127.0.0.1:8023/ npm run probe`

### 这轮被逼出来的两处"看似探针坏了"

1. **`require('./_browser')` 找不到** —— Node 的 CJS 解析只尝试 `.js/.json/.node`，**不含 `.cjs`**。
   必须写全 `require('./_browser.cjs')`。
2. **`probe:demo` 在本地跑 8/10，线上 10/10** —— 不是回归：云端会校验 OAuth callback 域名，
   `127.0.0.1` 不在白名单，`authorize` 直接 400、二维码拉不出来。
   ⚠️ 顺带纠正一个此前记录失真：之前"本地 10/10"其实是**打到了线上** ——
   该探针读的是 `PROBE_URL`，而当时传的是 `SITE`，环境变量名不同、被静默忽略。
   现已在本地地址时于汇总后打印说明，避免下一个人去白抓 bug。

### 探针改成三态（PASS / FAIL / SKIP）

线上旧产物是**单包**，根本没有 `ParallelView-*.js`，第 9 项「懒加载失败降级」掐不到 chunk。
第一次跑出来是 FAIL（`waitForFunction` 超时），这属于"误报"：会被读成"降级功能坏了"。
改成三态，并统计"跳过"项：

| 目标 | 结果 |
|---|---|
| 本地新产物（有按需 chunk + 边界） | **9/9 通过**（第 9 项：`chunk 中断 1 次，显示提示卡（有）且顶部导航仍可用（是=非白屏）`） |
| 线上旧产物（单包，无边界） | **8/8 通过（另有 1 项跳过）** —— 第 9 项明确标 SKIP 而非 PASS |

> 三态不是"宽容"，是**准确**：把测不到的东西记成 PASS 才是真的失职；记成 FAIL 则会训练人忽略红灯。

## 一·F、第六批：从"优化"转向"找病"—— 三个能上线但演示会翻车的缺陷（2026-10-21 16:45）

### 怎么发现的（顺序很重要）

1. 先量后端：8 个 GET 全部 2–14ms ⇒ **性能已经不是瓶颈**，继续优化是自欺。
2. 于是问"哪段代码没有被任何测试/探针覆盖"——答案是**产品主路径第 ③ 步（调课沙盘）**。
   `probe_ui_flow.cjs` 点完"我的课程"直接跳去了"并行排课"，把最核心的那一页跳过了。
3. 新写探针（`probe_reschedule_flow.cjs`）一跑，三个缺陷自己跳出来（见下）。
4. 顺带发现：`/impact-analysis` 返回 `affected_teachers: ["2024级应用化学1、2班"]` —— 班级名出现在教师栏。

### R-19 🔴 P0 · 一个慢请求把全站冻住 8 秒

| 项 | 内容 |
|---|---|

### R-25 🔴 P0 · 探针「📊 数据看板」这一项**永远 PASS**（假绿）

| 项 | 内容 |
|---|---|
| 现象 | 把 `/api/reschedule/data-audit` 用 `route.abort()` **故意打断**，探针仍报 `PASS 数据看板 — 体检/统计内容已渲染` |
| 根因 | 等待条件写的是 `/数据体检\|冲突\|统计/`，而视图副标题「对现有实验安排表做一键体检：数据覆盖情况 + 教室/教师**冲突**扫描」是**静态文案**，页面一挂载就命中；最终断言 `/数据体检\|健康\|冲突/` 同样只吃到了这句副标题 |
| 危害 | 这是"零覆盖"的伪装形态：看起来有一项在守着数据看板，实际从上线到现在**一次都没守过**。前七批所有"无回归"的结论里，这一项都是无效票 |
| 修复 | 只认**数据到达后才会出现**的字符串：`共 \d+ 条安排` / `\d+ 间场地` / `[\d.]+%` + `平均教室利用率`，并要求三态结论之一（整体健康 / 发现潜在冲突 / 无冲突但有缺口），外加"不得出现失败卡"的反断言 |

## 三、评估过但不建议做的（留档以免重排）

| 想法 | 结论 |
