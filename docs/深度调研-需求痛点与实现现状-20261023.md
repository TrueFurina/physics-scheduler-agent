## 一、需求本质（一句话）

**这不是"排课系统"，是"物理实验教学场景下、教务给定时间范围内的实验项目 × 学生组的批量分配器 + 冲突分级器 + 教务标准课表出稿器"。**

三个不能省的定语：

1. **物理实验教学场景**——一门课 = N 个实验项目 × M 个学生组，每组教师/场地/时段可能都不同。这是与普通排课软件的根本差异，也是访谈里点名的市场空白（"排实验课的软件是针对老师的，老师哪有那么多实验呢"）。
2. **教务给定时间范围内**——培养方案、学期总周次、班级上课的星期/节次由教务处/教学秘书给定，我们**只在给定窗口内**排实验内容（项目×组→教师×场地），不越权决定时间。
3. **批量分配 + 冲突分级 + 教务出稿**——用户不是要"AI 排课"这么抽象的东西，而是要三件具体的事：**一次性排完一个班所有实验项目**、**告诉我哪些冲突必须改哪些可以强推**、**导出班级/场地两类教务能收的标准课表**。

## 二、真实用户与工作流（不是"教师"，是"实验管理人员 + 教学秘书"）

| 角色 | 干什么 | 与本系统的关系 |
|---|---|---|
| 教学秘书 | 按当年教学大纲把含实验环节的课程导入教务系统 | **上游**：产出主数据（课程/项目/班级） |
| 实验管理人员（本项目真正的用户） | 核查/新建实验项目、指定排课人员、分组、选教师、定时/地、保存、导出 | **主用户**：本项目覆盖他的第 2–5 步 |
| 排课人员 | 具体执行分组→选师→定时→选场地→保存 | 同上 |
| 任课教师 | 通过本系统发起调课申请 | **次要用户**：调课闭环 |
| 管理员（教务） | 审批调课 | 同上 |
| 学生 | 咨询选课 / 实验辅导 | 边缘模块，非核心 |

**5 步工作流与本系统的覆盖度**（战略复盘的核心结论）：

| 步 | 内容 | 覆盖 |
|---|---|---|
| 1 | 按当年大纲导入含实验的课程 | ✅ 已覆盖（`/upload-master` + 五表 CRUD） |
| 2 | 核查/新建实验项目 | ✅ 已覆盖（主数据 CRUD + 台账导入） |
| 3 | 指定排课人员、分配权限 | ⚠️ 部分（有 admin，但没有细粒度角色/权限） |
| 4 | 分组→选师→定时→选地→保存（**每项目一遍**） | ✅ 且比他快（CP-SAT 一次解完，17/17 班、171/171 任务、410 条方案） |
| 5 | 导出班级课表、场地课表 | ✅ 已覆盖（R-46，17 页 433 行；10 室 433 行） |

**关键判断（来自战略复盘）**：本项目的定位应当写成"**第 4–5 步的加速器 + 第 1–2 步的轻量替代品**"，不是"取代教务系统"。含糊会被 17 年经验的实验管理人员当场问穿。

## 三、真正的痛点（按分量排序，不是按实现难度）

### 痛点 1（🔴 一号痛点，访谈与座谈两次点名）
**现行系统不支持"并行排课"，N 个项目 × M 个组 = N×M 次完整重复操作。**

访谈原话："我本来说我排一个课，所有的实验项目 1、2、3 列出来，这里教师，学生第一组、第二组我都可以直接分了……直接就可以排。" / "**现在我们的痛点就在这里。重复性太大了。**" / "就像 AI 一键全部完成。"

**已实现**：R-33/R-37/R-41/R-44/R-51/R-52/R-59/R-60 一系列迭代，做到：
- 单班：CP-SAT 一次求解一个班的全部（项目×组），17/17 班通过；
- 全校：一键排全校 17 个班，410 条方案，跨班同格同教室/同教师 0 处；
- 灰箱：教秘只给班级/项目/组三列，教师/场地/星期/节次/周次缺失时按主数据自动补全（负载最轻教师优先），并**逐条报告"我替你做了什么决定"**（15 条假设进 `assumptions`）；
- 教务时间范围：主数据存班级的 `weekday/time_slots/week_min/week_max`，求解器**从主数据读**，不再自己推断。

### 痛点 2（🔴 座谈一号行动项）
**数据库不完善——实验项目/教师/场地/班级/课程没有独立实体，信息无法灵活调取。**

**已实现**：R-47/R-48/R-50/R-53/R-55/R-58 一系列迭代：
- 五张实体表（课程/实验项目/教师/场地/班级）可增删改；
- 从安排表反推自愈（重启不丢）；
- 版本化落盘 `master_store.json`（原子写 + 指纹失效）；
- 台账 Excel 导出 → 离线维护 → 导回（往返无损，17 班名字里带顿号也不会切碎）；
- 绪论/考试类项目**登记在册但绝不进求解器**（`schedulable` 是项目名的派生函数，不可被用户覆盖）。

### 痛点 3（🟠 座谈明确要求）
**冲突分级——核心冲突（场地/教师/整组）必须改；轻微冲突（个别学生）可强制通过。**

**已实现**：R-56 落地核心部分（三类分别识别 + `severity/label/fix_hint/can_force`）。
**未实现**：轻微冲突（个别学生）—— 依赖学生课表，涉及 PII 暴露边界未获确认，`/upload-student` 是 `require_admin` 且**前端零调用**。`force` 参数刻意没做（只做核心冲突时是死参数）。

### 痛点 4（🟠 座谈明确要求）
**导出班级课表、场地课表（教务标准输出物）；跨课程合并 + 撞车标记。**

**已实现**：R-46 两类课表导出；R-57 班级课表加课程列 + 按课程分块 + 跨课程撞车在表尾单列；R-59 一键自动排课的初稿导出（总表 + 每班一页，18 页）。

### 痛点 5（🟡 演示层）
**教师调课闭环**——PRD v1.0 的原始需求，已完整落地（自然语言解析 + 三重冲突筛选 + 沙盘 + 影响分析 + 提交/审批/落地）。R-36 修掉了"审批通过课表一个字节都没变"的假闭环。

### 痛点 6（🟢 学生端，价值有限）
选课咨询 / 实验辅导 LLM 问答——已实现，但访谈与座谈全程未提。是"业务闭环演示需要"，不是用户痛点。

## 四、输入输出与数据流

### 输入（三条通道）

| 通道 | 端点 | 内容 | 权威度 |
|---|---|---|---|
| **A. 教务给定"课程总时间范围"** | 主数据 CRUD `/master/classes`（`weekday/time_slots/week_min/week_max`） | 班级上课的星期/节次/周次窗口 | **最高**（求解器直接读，不再推断） |
| **B. 已排好的实验安排表** | `POST /upload` → `schedule.xlsx` | 433 条历史/在排记录（`大学物理实验安排表 (周)` 工作表） | 高（占用来源，主数据反推基线） |
| **C. 未排课的教学大纲清单** | `POST /upload-master` | 班级/项目/组三列即可（教师/场地/时间可缺） | 中（灰箱补全后进入求解） |

**换学校**：只要 A+B+C 任一到位即可跑；`find_schedule_sheet` 容错定位工作表名（不再硬编码带尾随空格的旧名字）。

### 数据模型（内存 + 落盘）

```
ScheduleDatabase (excel_parser.py)
├── entries: ScheduleEntry[433]   # 已排课程行
│     · class_name, group, project, room, teacher, week, weekday, time_slot
│     · time_raw (原表写法), blocked (真实占住的全部节次) ← R-40 关键
├── pending: PendingTask[]        # 未排课任务（R-48 新增独立实体）
├── skipped: SkippedRow[]         # 时段认不出的行（不静默丢，R-35）
└── load_report                    # 上传/加载回执：解析/待排/丢弃计数

MasterData (master_data.py)
├── courses / experiments / teachers / rooms / classes  # 五张实体表
├── classes[*].weekday/time_slots/week_min/week_max/weekdays  # 教务给定时间范围
└── experiments[*].schedulable    # 派生自项目名，绪论/考试=False

master_store.json (backend/app/data/, gitignored)
└── 原子写 + schedule_fingerprint + schema_version=2
    · 指纹变（安排表被替换）→ 丢弃旧落盘按新表反推
    · 文件损坏 → fail-closed 回退反推基线
```

### 输出（三类）

| 类别 | 端点 | 用途 |
|---|---|---|
| **求解方案** | `POST /parallel/solve`（单班）/ `POST /parallel/solve-all`（全校）/ `POST /auto-schedule`（全校教师×课程粒度） | 教秘核对/微调 |
| **教务标准课表** | `GET /export/class-schedule`（17 页 433 行）/ `GET /export/room-schedule`（10 室 433 行）/ `GET /export/master-workbook`（台账可导回）/ `POST /auto-schedule/export`（初稿 18 页） | 提交教务/存档 |
| **体检与统计** | `GET /data-audit`（三类核心冲突 + 跨课程撞车 + 缺口）/ `GET /stats`（真实利用率 9.4% + 容量口径） | 数据健康度 |

### 核心数据流

```
上传/主数据 CRUD ─┬─→ ScheduleDatabase ─┐
                  │                     │
                  └─→ MasterData ───────┤
                                        ▼
                          ┌─────────────────────────┐
                          │ 求解器（CP-SAT）        │
                          │ · parallel_scheduler    │  单班/全校组级
                          │ · auto_scheduler        │  全校教师×课程
                          │ 读主数据的时间范围      │
                          │ 读已排表做占用避让      │
                          │ 灰箱缺项按主数据补全    │
                          └───────────┬─────────────┘
                                      ▼
                     方案 + assumptions（每个替你做的决定）
                                      ▼
                     导出 Excel / 体检 / 审批闭环
```

### P1-1 · 权限模型粗糙（只有 admin 一个角色）

- 座谈明确要求："指定排课人员，分配对应实验课程的排课操作权限"

- 差距：没有"某实验管理人员只能排某几门课"的细粒度权限
- **优先级**：中——单校单学院场景够用，多学院/多校区推广时必须做

### P1-2 · 教务系统对接（"最为关键的一环"）未做

- 座谈金句："对，这个和教务系统打通是最为关键的一环。"

- 差距：无法实时看到理论课占用；冲突检测只在实验课内部
- 应对：可作为插件（座谈给出的两条路径之一：导数据 or 做插件）
- **优先级**：中——依赖学校接口，短期无解；但要在架构上留好接口位

### P1-3 · 教室容量校验被刻意删掉（R-38）

- 安排表没有容量字段，此前用"名字里有没有'大'字"编造，把 50% 任务判死
- 现状：不做容量校验，`note` 明写"容量未校验（安排表无容量字段）"
- 差距：主数据 `rooms` 表可以加 `capacity` 字段，但**没有数据来源**
- **优先级**：低——诚实告知胜过编造数字，等主数据台账实际使用后再决定

### P2-1 · 沙箱残留（无害但会累积）

### P2-2 · PDF 学生课表解析器过度调试，投入产出比低（历史遗留）

- `pdf_schedule_parser.py` 存在但从未被主路径调用

- **优先级**：低——不删也不动，避免制造新的死代码岛

### P2-3 · 演示数据（D-8）审批台 0 工单、唯一管理员=唯一申请人

- 需要第二个真实登录账号才能演示完整审批链

## 九、方法论沉淀（这个项目最贵的教训）

1. **探针的价值等于它敢红的能力**（R-25 假绿、R-33 前三版测试无效、R-40 校验器与被验对象共用错误假设）——**新建的判据必须先在"已知有缺陷"的版本上跑出红来，才算数**。
2. **合成数据全绿不代表真实数据过**（R-55 班名自带顿号把 17 班切成 29 班）——真实表往返必须写进回归。
3. **并发是慢请求缺陷的唯一显影液**（R-19 一个 `/chat` 冻住全站 8 秒）——单用户串行点测永远测不出。
4. **静默半导入比报错危险**（R-35 时段认不出整行丢、R-26 空场地报假冲突）——丢弃/异常必须留痕、必须报数。
5. **写路径的失败不会让页面报错，只会让数据悄悄没变**（R-36 审批通过课表一个字节没变）——写路径必须独立探针。
6. **编造的数字伪装成资源瓶颈比诚实的"未校验"更危险**（R-38 教室容量按"名字里有没有'大'字"猜）——宁可让读者知道"这一维没管"。
7. **需求方不是我的用户视角时，"我没看到需求"≠"没有需求"**（项目总结）——论文调研 + 一手访谈 + 座谈三次交叉验证才敢下判断。
