## 〇、硬边界（用户 2026-10-23 拍板，高于一切功能讨论）

> **"永远不要管学生的任何事务，因为教务系统那边已经事先分配好了课程，我们这边只是分配实验项目与老师。"**

这条边界把产品定位收窄成一句更精确的话：

**我们是"教务给定时间范围内、把（实验项目 × 学生组）分配给（教师 × 场地）的求解器 + 冲突分级器 + 教务标准课表出稿器"。学生个体、选课、成绩、考勤——一概不碰。**

由此产生的**强制结论**（不是建议，是边界）：

| 对象 | 处置 | 理由 |
|---|---|---|
| 学生课表模块（`/upload-student`、`StudentSchedule`、`student_data.py`、`student_schedule.py`、`pdf_schedule_parser.py`） | **删除** | 学生事务出局；R-39 已证实"学生维度从未生效"，是死代码 |
| 三重冲突检查的"学生"腿 | **删除**，改"两重"（教室/教师）+ 整组 | 同上 |
| 冲突分级的"轻微冲突（个别学生）"+ `force` 参数 | **永久不做** | 没有学生数据就没有"个别学生冲突"；`force` 只做核心冲突时是死参数 |
| `/impact-analysis` 的 `affected_students` | **删除** | 只留 `affected_teachers` / `affected_rooms` / `self_busy_slots` |
| `/course-select`（选课咨询，PRD F7） | **删除** | 学生端，出局 |
| `/experiment-tutor`（实验辅导，PRD F8） | **保留但改造定位** | 从"学生问实验原理"改成"排课人员/教师查实验规范"（项目学时/场地/步骤），服务于排课核对 |
| "学生组"（group） | **保留** | 组是**排课输入单元**（名单由教务/排课人员给定），我们只做组级互斥，不管理组内学生——**符合**边界 |

## 一、需求本质（一句话）

**这不是"排课系统"，是"物理实验教学场景下、教务给定时间范围内的实验项目 × 学生组的批量分配器 + 冲突分级器 + 教务标准课表出稿器"。**

三个不能省的定语：

1. **物理实验教学场景**——一门课 = N 个实验项目 × M 个学生组，每组教师/场地/时段可能都不同。这是与普通排课软件的根本差异，也是访谈里点名的市场空白（"排实验课的软件是针对老师的，老师哪有那么多实验呢"）。
2. **教务给定时间范围内**——培养方案、学期总周次、班级上课的星期/节次由教务处/教学秘书给定，我们**只在给定窗口内**排实验内容（项目×组→教师×场地），不越权决定时间。
3. **批量分配 + 冲突分级 + 教务出稿**——用户要的是三件具体的事：**一次性排完一个班所有实验项目**、**告诉我哪些冲突必须改**（注：边界收窄后不再有"可强推"的轻微冲突）、**导出班级/场地两类教务能收的标准课表**。

## 二、真实用户与工作流（不是"教师"，是"实验管理人员 + 教学秘书"）

| 角色 | 干什么 | 与本系统的关系 |
|---|---|---|
| 教学秘书 | 按当年教学大纲把含实验环节的课程导入教务系统 | **上游**：产出主数据（课程/项目/班级） |
| 实验管理人员（本项目真正的用户） | 核查/新建实验项目、指定排课人员、分组、选教师、定时/地、保存、导出 | **主用户**：本项目覆盖他的第 2–5 步 |
| 排课人员 | 具体执行分组→选师→定时→选场地→保存 | 同上 |
| 任课教师 | 通过本系统发起调课申请；查实验规范 | **次要用户**：调课闭环 + 实验规范查询 |
| 管理员（教务） | 审批调课 | 同上 |
| ~~学生~~ | ~~咨询选课 / 实验辅导~~ | **出局**（硬边界：不管学生事务） |

**5 步工作流与本系统的覆盖度**（战略复盘的核心结论）：

| 步 | 内容 | 覆盖 |
|---|---|---|
| 1 | 按当年大纲导入含实验的课程 | ✅ 已覆盖（`/upload-master` + 五表 CRUD + R-63 导入向导） |
| 2 | 核查/新建实验项目 | ✅ 已覆盖（主数据 CRUD + 台账导入 + 预览） |
| 3 | 指定排课人员、分配权限 | ⚠️ 部分（有 admin，但没有细粒度角色/权限） |
| 4 | 分组→选师→定时→选地→保存（**每项目一遍**） | ✅ 且比他快（CP-SAT 一次解完，17/17 班、171/171 任务、410+ 条方案；R-61 可写回安排表） |
| 5 | 导出班级课表、场地课表 | ✅ 已覆盖（R-46 两类课表；R-62 周课表网格可视化） |

**关键判断（来自战略复盘）**：本项目的定位应当写成"**第 4–5 步的加速器 + 第 1–2 步的轻量替代品**"，不是"取代教务系统"。含糊会被 17 年经验的实验管理人员当场问穿。

## 三、真正的痛点（按分量排序，不是按实现难度）

### 痛点 1（🔴 一号痛点，访谈与座谈两次点名）
**现行系统不支持"并行排课"，N 个项目 × M 个组 = N×M 次完整重复操作。**

访谈原话："我本来说我排一个课，所有的实验项目 1、2、3 列出来，这里教师，学生第一组、第二组我都可以直接分了……直接就可以排。" / "**现在我们的痛点就在这里。重复性太大了。**" / "就像 AI 一键全部完成。"

**已实现**：R-33/R-37/R-41/R-44/R-51/R-52/R-59/R-60/R-61 一系列迭代，做到：
- 单班：CP-SAT 一次求解一个班的全部（项目×组），17/17 班通过；
- 全校：一键排全校 17 个班，410+ 条方案，跨班同格同教室/同教师 0 处；
- 灰箱：教秘只给班级/项目/组三列，教师/场地/星期/节次/周次缺失时按主数据自动补全（负载最轻教师优先），并**逐条报告"我替你做了什么决定"**（假设进 `assumptions`）；
- 教务时间范围：主数据存班级的 `weekday/time_slots/week_min/week_max`，求解器**从主数据读**，不再自己推断；
- **方案落地（R-61）**：全校方案不再只活在内存——差异预览（四类账）→ 采纳写回安排表 → 撤销恢复快照，三步可回退，重启重放存活。

### 痛点 2（🔴 座谈一号行动项）
**数据库不完善——实验项目/教师/场地/班级/课程没有独立实体，信息无法灵活调取。**

**已实现**：R-47/R-48/R-50/R-53/R-55/R-58/R-63 一系列迭代：
- 五张实体表（课程/实验项目/教师/场地/班级）可增删改；
- 从安排表反推自愈（重启不丢）；版本化落盘 `master_store.json`（原子写 + 指纹失效）；
- 台账 Excel 导出 → 离线维护 → 导回（往返无损，17 班名字里带顿号也不会切碎）；
- 绪论/考试类项目**登记在册但绝不进求解器**（`schedulable` 是项目名的派生函数，不可被用户覆盖）；
- **数据导入向导（R-63）**：外校格式 Excel 的"页→列→字段"映射**先看再导**，预览与写库共用同一份解析代码，未识别列/统计列/样本行全部摊开。

### 痛点 3（🟠 座谈明确要求 → 边界收窄后只剩核心部分）
**冲突分级——核心冲突（场地/教师/整组）必须改。**

**已实现**：R-56 落地核心三类（分别识别 + `severity/label/fix_hint`）+ 体检整组维度。
**永久不做**：~~轻微冲突（个别学生）可强制通过~~ —— **硬边界排除**（不管学生事务 ⇒ 没有"个别学生冲突"这一类 ⇒ `force` 参数永久不引入）。座谈原话"多数小冲突可直接强制通过"在本产品边界内**不适用**，因为那类冲突根本不在我们的数据范围里。

### 痛点 4（🟠 座谈明确要求）
**导出班级课表、场地课表（教务标准输出物）；跨课程合并 + 撞车标记；排课结果可视化。**

**已实现**：R-46 两类课表导出；R-57 班级课表加课程列 + 按课程分块 + 跨课程撞车在表尾单列；R-59 一键自动排课初稿导出（总表 + 每班一页）；**R-62 周课表网格**（7 天 × 4 时段全景、点格详情、班级/场地筛选、冲突标记，README 路线图头号未做项已清）。

### 痛点 5（🟡 演示层）
**教师调课闭环**——PRD v1.0 的原始需求，已完整落地（自然语言解析 + 冲突筛选 + 沙盘 + 影响分析 + 提交/审批/落地）。R-36 修掉了"审批通过课表一个字节都没变"的假闭环。注：边界收窄后影响分析去掉 `affected_students`。

### 痛点 6（🟢 已按边界处置）
~~选课咨询 / 实验辅导 LLM 问答~~ —— **选课咨询删除**（学生端出局）；**实验辅导保留但改造**为"排课人员/教师查实验规范"。访谈与座谈全程未提学生端，本就是"业务闭环演示需要"而非用户痛点。

## 四、输入输出与数据流

### 输入（三条通道）

| 通道 | 端点 | 内容 | 权威度 |
|---|---|---|---|
| **A. 教务给定"课程总时间范围"** | 主数据 CRUD `/master/classes`（`weekday/time_slots/week_min/week_max`） | 班级上课的星期/节次/周次窗口 | **最高**（求解器直接读，不再推断） |
| **B. 已排好的实验安排表** | `POST /upload` → `schedule.xlsx` | 433 条历史/在排记录 | 高（占用来源，主数据反推基线） |
| **C. 未排课的教学大纲清单** | `POST /upload-master`（+ R-63 `POST /master/tasks-preview` 预览） | 班级/项目/组三列即可（教师/场地/时间可缺） | 中（灰箱补全后进入求解） |

**换学校**：只要 A+B+C 任一到位即可跑；`find_schedule_sheet` 容错定位工作表名；R-63 导入向导应对外校列名差异（「项目名称」「任课教师」「实验室」「教学班」…）。

### 数据模型（内存 + 落盘）

```
ScheduleDatabase (excel_parser.py)
├── entries: ScheduleEntry[433]   # 已排课程行
│     · class_name, group, project, room, teacher, week, weekday, time_slot
│     · time_raw (原表写法), blocked (真实占住的全部节次) ← R-40 关键
├── pending: PendingTask[]        # 未排课任务（R-48 独立实体）
├── skipped: SkippedRow[]         # 时段认不出的行（不静默丢，R-35）
└── load_report                    # 上传/加载回执：解析/待排/丢弃计数

MasterData (master_data.py)
├── courses / experiments / teachers / rooms / classes  # 五张实体表
├── classes[*].weekday/time_slots/week_min/week_max/weekdays  # 教务给定时间范围
└── experiments[*].schedulable    # 派生自项目名，绪论/考试=False

plan_landing.py (R-61)             # 方案落地账本 landed_plans（与 requests.db 同库）
master_store.json (backend/app/data/, gitignored)  # 原子写 + 指纹 + schema_version=2
```

### 输出（四类）

| 类别 | 端点 | 用途 |
|---|---|---|
| **求解方案** | `POST /parallel/solve`（单班）/ `POST /parallel/solve-all`（全校）/ `POST /auto-schedule`（全校教师×课程粒度） | 教秘核对/微调 |
| **方案落地（R-61）** | `POST /parallel/land/preview`（差异预览，不写）/ `POST /parallel/land`（采纳，admin）/ `POST /parallel/land/undo`（撤销，admin）/ `GET /parallel/land/status` | 把方案写回安排表，三步可回退 |
| **教务标准课表 + 可视化** | `GET /export/class-schedule` / `GET /export/room-schedule` / `GET /export/master-workbook` / `POST /auto-schedule/export` / **`GET /schedule-grid`（R-62 周课表网格）** | 提交教务/存档/一眼核对 |
| **体检与统计** | `GET /data-audit`（三类核心冲突 + 跨课程撞车 + 缺口）/ `GET /stats`（真实利用率 9.4% + 容量口径） | 数据健康度 |

## 九、方法论沉淀（这个项目最贵的教训）

1. **探针的价值等于它敢红的能力**（R-25 假绿、R-33 前三版测试无效、R-40 校验器与被验对象共用错误假设、R-64"总条数没变证明不了没写入"）——**新建的判据必须先在"已知有缺陷"的版本上跑出红来，才算数**。
2. **合成数据全绿不代表真实数据过**（R-55 班名自带顿号把 17 班切成 29 班）——真实表往返必须写进回归。
3. **并发是慢请求缺陷的唯一显影液**（R-19 一个 `/chat` 冻住全站 8 秒）——单用户串行点测永远测不出。
4. **静默半导入比报错危险**（R-35 时段认不出整行丢、R-26 空场地报假冲突、R-61 长实验只检一种表示会静默截短）——丢弃/异常必须留痕、必须报数。
5. **写路径的失败不会让页面报错，只会让数据悄悄没变**（R-36 审批通过课表一个字节没变、R-61 落地预览偷写）——写路径必须独立探针 + 内容签名对账。
6. **编造的数字伪装成资源瓶颈比诚实的"未校验"更危险**（R-38 教室容量按"名字里有没有'大'字"猜）——宁可让读者知道"这一维没管"。
7. **代码参数必须与文档记录的性能证据一致**（R-61 `flatten_seconds=3.0` 比文档"7 秒可解"紧 2 秒 ⇒ CI 绿是运气）——否则真实表测试 51/171 失败。
8. **需求方不是我的用户视角时，"我没看到需求"≠"没有需求"**（项目总结）——论文调研 + 一手访谈 + 座谈三次交叉验证才敢下判断。
9. **产品边界由用户拍板，不由技术惯性决定**（2026-10-23 学生事务硬边界）——做了 60+ 批修复后，一句"永远不管学生"让一整类功能（学生课表/选课/轻微冲突/force）从"待办"变"待删"。**边界比功能更根本。**
