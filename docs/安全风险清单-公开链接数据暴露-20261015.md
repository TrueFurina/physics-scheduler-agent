## 一、平台定位（判定基准）

| 项 | 结论 | 依据 |
|---|---|---|
| 目标用户 | **排课管理员 / 教学秘书（教秘）**为主，实验教师为操作者 | `docs/演讲稿.md:68`；`:60` "没人做'排课管理员日常调课/冲突评估'——这是我们的差异化" |
| 真实痛点来源 | 教秘向教师收取实验课安排 → 逐项目排课重复劳动 | `docs/需求验证-教师深度访谈-20261008.md:11-13` |
| 学生是否为用户 | **否** | `docs/演讲稿.md:243`、`:271` 作者结论 |
| 学生课表的角色 | **三重冲突检查的输入数据**（教室/学生/教师），非学生端功能 | `docs/演讲稿.md:102` |
| 教师姓名的角色 | **业务必需的演示主体**（13 位授课教师即调课发起者） | `docs/调课模块需求文档-v1.1.md:48` |

**判定基准**：合法数据使用者是教秘。判风险的标准是"**匿名公网访客有没有权读到**"，不是"数据真不真"。据此教师姓名属教秘正常工作数据 → **不是风险**（R-02 已撤回）。

**用户明确要求**：线上与本地数据一致，教师姓名必须保留 → 加固方案据此设计为"**加服务端门禁，不动一行数据**"。

## 二、结论

线上服务的 `/api/reschedule/**` 原先**完全没有鉴权**：写接口（清空工单、审批、替换排课表）与真实学生身份接口对匿名访客开放；前端明文口令写在 bundle 里。

**根因两条**：
1. `backend/app/main.py:45` 注册路由无 `dependencies=`，`reschedule.py` 的 `APIRouter()` 无依赖，`grep -c "Depends("` 结果为 **0**。
2. `sites` 部署上传器只排除 `node_modules`/`.git`/构建产物，**不读 `.gitignore`** —— 作者已在 `reschedule.py` 注释中写明并堵住排课表一路，同一根因的其余路径未覆盖。

**加固方案**：服务端 HMAC 会话门禁 + 关闭发布态文档 + 上传文件名净化 + 前端移除明文口令。**未改动任何演示数据**。

#### 坑 3：限流第一版**线上完全没生效**（本轮最有价值的发现）

本地压测第 31 次必 429，线上同样压测 **34 次全是 401、一次 429 都没有**。

逐项排查后的结论：
- 沙箱是**单进程有状态**服务（用 `load-default` 后 `/status` 稳定变 `loaded:true` 证伪"多副本各自计数"）；
- 边缘网关**会覆盖**客户端自带的 `X-Forwarded-For` / `X-Real-IP`（两种头分别固定发 34 次，均不影响判定）；
- 它注入的源 IP **逐次变化** ⇒ "单 IP 桶"在线上永远攒不满。

**修法**：增加一维**客户端指纹**（User-Agent + Accept-Language 的短哈希），与源 IP、全站桶各自独立计数、任一超限即拦。指纹在同样压测下稳定命中 → 把一条**无法验证的防护**变成可验证的。
**局限已写进代码**：指纹与 IP 都是客户端可伪造的，同时轮换 UA 与出口 IP 的攻击者只剩全站桶兜底；它的定位是"抬高滥用成本、挡住无脑脚本"，不是身份级访问控制。

## 九、R-18 · 线上可用性缺陷（v11 新增并已修复，待发布）

用户报告：「这个和本地是不是不一样，而且显示**加载课程总览失败：请先加载实验安排表（/load-default）**」。这是**可用性缺陷，不是安全缺口**，但它会在演示时直接挡住「并行排课」这一页，故单列。

### 现场复现（2026-10-21 15:11 实测线上）

```
GET /api/reschedule/status            → {"loaded":false,"total_entries":0,"teachers":[]}
GET /api/reschedule/parallel/overview → {"detail":"请先加载实验安排表（/load-default）"} [HTTP 400] 0.30s
```

同一时刻产物 hash 与本地**完全一致**（`index-CBVV35EQ.js`）⇒ **不是版本差异**，是运行时状态差异。

### 根因（三层，缺一不可）

| # | 层 | 事实 | 后果 |
|---|---|---|---|
| 1 | 后端 | 排课数据只存在**进程内存**（`ScheduleDatabase.loaded/entries`），无持久化 | 沙箱回收/重启后内存清零 |
| 2 | 后端 | 原先 **8 个数据接口**在未加载时直接 `raise HTTPException(400, "请先加载实验安排表")` | 冷进程下所有数据页不可用，且文案引导用户去点一个**界面上不存在的入口** |
| 3 | 前端 | 只在**页面挂载时**自动 `load-default` 一次，**无重试、无重新加载按钮** | 若页面打开后进程被回收，或首次请求因冷启动失败，用户只能手动刷新 |

> ⚠️ **v10 错判更正**：v10 写「冷启动不会空白：`App.tsx:405-417` 进入即自动 load-default」——该结论只覆盖"页面与进程同时冷启动"，**没覆盖"页面已打开、进程随后被回收"**，也没覆盖"首次请求因沙箱唤醒超时失败"。两者都会让用户卡死。**读代码得出的"已覆盖"不能替代实测。**

### 修复（本次）

| 文件 | 改动 |
|---|---|
| `backend/app/api/reschedule.py` | 新增 `_ensure_loaded()`：8 个数据接口在访问数据前**自动恢复**（默认表存在就直接加载，双检锁保证 433 行只解析一次）；`/load-default` 保留且幂等，但不再是使用前提。404 文案改为"服务器上未找到 xxx，请联系管理员处理"（原先"请先上传"会误导用户去找不存在的上传入口） |
| `backend/app/api/reschedule.py` | **顺带修掉一个潜伏的路径解析缺陷**：`_REPO_ROOT` 原为四层 `os.path.dirname` 连乘，而 `dirname` **不消解 `..`** —— 以 `backend/tests/../app/...` 这类路径导入时（测试里正是如此），仓库根会被算成 `backend/tests`，于是**静默回退到脱敏表**（教师名变「教师A」）。改为 `abspath` 规范化 + `backend/app` marker 向上探测，失配再退回规范化四层 |
| `frontend/src/App.tsx` | 新增 `withRetry()`：首屏初始化与「并行排课总览」各做 3 次退避重试（0/0.7/1.6s）；失败文案追加"（可刷新页面重试）"。重试覆盖的是**后端根本收不到请求**的情况（沙箱唤醒超时/5xx），与后端自愈互补 |
| `backend/tests/test_autoload.py`（新增 6 项） | ① 冷进程下 3 个数据接口应自愈为 200 且不再出现旧文案；② 用户报错的具体接口自愈后必须**真的返回课程数据**（非空壳 200）；③ 自愈只解析一次（幂等）；④ 默认表真缺失时仍如实 404；⑤ **路径解析回归**：含 `..` 的导入路径下仓库根不得算成 `backend/tests`；⑥ marker 缺失时退化路径仍规范化 |
